# Parte I — Fundamentos

## 1. Objetivo y alcance

### Objetivo

Producir una librería de **35 Agent Skills bilingües (ES/EN)** que cubre end-to-end el desarrollo web con ArcGIS Maps SDK for JavaScript 5.0+, cumpliendo:

- El **Agent Skills Specification** oficial (agentskills.io)
- Las recomendaciones de la guía oficial de Anthropic **"Complete Guide to Building Skills for Claude"**
- Las **release notes 5.0** del SDK (CDN unificada, deprecación AMD, eliminación `__esri`)

### Alcance In-Scope

| ✅ | Item |
|---|---|
| ✅ | 35 skills cubriendo Core, Layers, Visualization, Interaction, Widgets, Spatial, Services, Specialized y New-in-5.0 |
| ✅ | Cada skill bilingüe (`SKILL.md` EN + `SKILL.es.md` ES) sincronizadas |
| ✅ | Progressive disclosure: SKILL.md ≤ 300 líneas, detalle en `references/` |
| ✅ | Scripts ejecutables verificables (`scripts/scaffold.sh`, snippets TypeScript) |
| ✅ | Tests de validación, smoke build y triggering evals automatizados en CI |
| ✅ | Compatibilidad con Claude Code, Cursor, GitHub Copilot, Codex, OpenCode |
| ✅ | Instalación via Skills CLI (`npx skills add`) y Claude Code marketplace |
| ✅ | Documentación pública en sitio estático |
| ✅ | Licencia MIT |

### Alcance Out-of-Scope

| ❌ | Item |
|---|---|
| ❌ | ArcGIS Pro Python (ArcPy) |
| ❌ | SDKs nativos iOS / Android / .NET / Java / Qt |
| ❌ | Game Engine SDKs (Unity, Unreal) |
| ❌ | Experience Builder widgets (proyecto independiente) |
| ❌ | ArcGIS REST API directo sin pasar por `@arcgis/core/rest` |
| ❌ | Versiones 4.x del SDK (legacy) |
| ❌ | Soporte oficial (es comunidad) |

### Asunciones

1. El equipo Esri continúa el patrón semver para 5.x
2. Map Components mantiene el modelo de slot + reference-element
3. La CDN unificada `js.arcgis.com/5.0/` se mantiene como entrypoint módulo
4. Los developers usan herramientas modernas (Vite, pnpm, TS strict)

### Restricciones

1. No usar contenido literal de docs oficiales sin reformulación (copyright)
2. No depender de cuentas comerciales de Esri para tests CI
3. Las skills deben funcionar con cuenta gratuita de ArcGIS Location Platform

### Dependencias externas

| Dependencia | Bloqueante | Plan B |
|---|---|---|
| GitHub disponible | Sí | Mirror en GitLab |
| npm registry disponible | Sí | Mirror local |
| Esri release notes accesibles | Medio | Cache de docs versionadas |
| Skills CLI (`vercel-labs/skills`) | Bajo | Instalación manual |

## 3. Glosario técnico

| Término | Definición |
|---|---|
| **Agent Skill** | Carpeta con `SKILL.md` + recursos que un agente AI consulta cuando la descripción matchea el query del usuario. |
| **Progressive disclosure** | Patrón de carga de skills en 3 niveles: metadata (siempre) → SKILL.md (al activarse) → references/scripts (bajo demanda). |
| **Map Components** | Web components (custom elements) del paquete `@arcgis/map-components` (`<arcgis-map>`, `<arcgis-scene>`, etc.). |
| **Core API** | API JavaScript clásica del SDK, accesible vía `@arcgis/core/*` (ej. `new MapView(...)`). |
| **Calcite** | Design system de Esri (`@esri/calcite-components`), provee shell, paneles, botones, iconos. |
| **ESM** | ECMAScript Modules (`import`/`export`). Reemplaza AMD/require en SDK 5.0. |
| **`$arcgis.import`** | Dynamic import en CDN para SDK 5.0, reemplazo de AMD `require()`. |
| **Reference element** | Patrón de Map Components para asociar widgets externos a un mapa mediante `reference-element` attribute. |
| **Webmap / Webscene** | Item ArcGIS Online/Enterprise que contiene un mapa o escena completo (capas, símbolos, popups). |
| **Autocasting** | Feature del SDK donde un objeto literal se convierte automáticamente a una clase del SDK. |
| **Renderer** | Define cómo se simboliza una capa (simple, unique-value, class-breaks, heatmap, dot-density). |
| **Smart Mapping** | Módulo del SDK que genera renderers automáticos basados en estadísticas de los datos. |
| **Arcade** | Lenguaje de expresiones de Esri para labels, popups, renderers, dashboards. |
| **DoD** | Definition of Done. Criterios objetivos para considerar una skill completa. |
| **GWT** | Given-When-Then. Formato de acceptance criteria. |
| **INVEST** | Independent, Negotiable, Valuable, Estimable, Small, Testable. Criterios de calidad de user stories. |

# Parte II — Estándares Técnicos

## 4. Anatomía completa de una skill

Cada skill es un directorio con la siguiente estructura **obligatoria** (✅) u **opcional** (🟡):

```
mi-skill/
├── SKILL.md                    ✅ Frontmatter + cuerpo en inglés (≤300 líneas)
├── SKILL.es.md                 ✅ Frontmatter + cuerpo en español (≤300 líneas)
├── AGENTS.md                   ✅ Decision tree + checklist rápida
├── references/                 ✅ Carpeta de detalles bajo demanda
│   ├── api-detail.md           ✅ Tablas de props/methods/events
│   ├── examples.md             ✅ Mínimo 3 ejemplos end-to-end
│   └── pitfalls.md             ✅ 5+ pitfalls extendidos
├── scripts/                    🟡 Si la skill genera proyectos o ejecuta tareas
│   ├── scaffold.sh             🟡 Bash que crea proyecto funcional
│   └── snippet-*.ts            🟡 Snippets TS standalone para smoke tests
├── assets/                     🟡 Imágenes/diagramas referenciados
│   └── architecture.svg
└── tests/                      ✅ Tests automatizados por skill
    ├── smoke.spec.ts           ✅ tsc + vite build pasan
    ├── integration.spec.ts     🟡 Playwright si aplica
    └── triggering.json         ✅ Prompts de eval para descripción
```

### Lectura recomendada por el agente AI

| Cuando el agente debe... | Lee |
|---|---|
| Decidir si la skill aplica | Solo metadata (frontmatter) |
| Empezar a resolver una tarea | `SKILL.md` (o `SKILL.es.md` si el query está en español) |
| Tomar decisiones arquitecturales rápidas | `AGENTS.md` |
| Necesita firma exacta de una API | `references/api-detail.md` |
| Necesita un ejemplo completo | `references/examples.md` |
| Encuentra un error inesperado | `references/pitfalls.md` |
| Generar un proyecto desde cero | `scripts/scaffold.sh` |

### Reglas de longitud

| Archivo | Límite | Acción si se supera |
|---|---|---|
| `SKILL.md` / `SKILL.es.md` | 300 líneas (warn) / 500 (error) | Mover detalle a `references/` |
| `AGENTS.md` | 100 líneas | Mantener solo decisiones |
| `references/*.md` | Sin límite, pero TOC obligatoria si >300 líneas | — |
| `description` en frontmatter | ~100 tokens | Reducir |

## 5. Schema completo de frontmatter

### Schema YAML obligatorio

```yaml
---
# === IDENTIDAD ===
name: arcgis-core-maps                         # OBLIGATORIO · debe coincidir con nombre del directorio
description: |                                  # OBLIGATORIO · ~100 tokens · es el trigger principal
  Initialize 2D MapView and 3D SceneView with ArcGIS Maps SDK 5.0. Covers
  basemap selection, view navigation, and the decision between Map Components
  (@arcgis/map-components) and Core API (@arcgis/core). Use this skill whenever
  the user creates a map, scene, basemap, or asks how to display geographic
  data on the web.

# === LOCALIZACIÓN ===
lang: en                                        # OBLIGATORIO · "en" o "es"

# === VERSIONADO ===
version: 0.1.0                                  # OBLIGATORIO · semver
status: stable                                  # OBLIGATORIO · stable | beta | deprecated
sdk_version: ">=5.0 <6.0"                       # OBLIGATORIO · rango semver del SDK
created: 2026-06-01                             # OBLIGATORIO · fecha ISO
updated: 2026-06-15                             # OBLIGATORIO · fecha ISO

# === CATEGORIZACIÓN ===
category: core                                  # OBLIGATORIO · core | layers | visualization | interaction | widgets | spatial | services | specialized | new-in-5.0
tags:                                           # OBLIGATORIO · array de strings
  - map
  - scene
  - basemap
  - view

# === DEPENDENCIAS ===
requires:                                       # OPCIONAL · skills hermanas requeridas
  - arcgis-starter-app
packages:                                       # OPCIONAL · npm packages que la skill asume instalados
  - "@arcgis/map-components@^5.0"
  - "@arcgis/core@^5.0"

# === COMPATIBILIDAD ===
agents:                                         # OPCIONAL · agentes verificados
  - claude-code
  - cursor
  - github-copilot
  - codex

# === METADATA ===
maintainer: "GeoAI LATAM"                       # OBLIGATORIO
license: MIT                                    # OBLIGATORIO
---
```

### Validación automática del frontmatter

El script `scripts/lint-frontmatter.js` valida:

1. `name` es kebab-case y matchea el directorio
2. `description` está entre 50 y 200 tokens
3. `lang` es `en` o `es`
4. `version` es semver válido
5. `status` ∈ {`stable`, `beta`, `deprecated`}
6. `sdk_version` es un range semver válido
7. `category` ∈ lista enumerada
8. `tags` tiene al menos 3 elementos
9. `created` y `updated` son fechas ISO válidas
10. `updated` ≥ `created`

### Sincronización ES/EN

El script `scripts/bilingual-sync.js` falla CI si:

1. Las secciones de ambos archivos no coinciden (mismo orden, mismos H2)
2. La diferencia de longitud entre ES y EN supera 15%
3. El número de bloques de código difiere
4. Hay un archivo y no el otro

## 8. Plantilla oficial de `AGENTS.md`

`AGENTS.md` es la guía rápida para el agente. **Es opcional cargarla** según el modelo, pero útil para decisiones arquitecturales sin abrir SKILL.md completo.

```markdown
# Agent Guide: [skill-name]

Quick-reference for [domain]. Read before deciding architecture or generating code.

## Quick Decision Tree

1. **Are you starting a new project?**
   - Yes → Use Map Components (`<arcgis-map>`)
   - No → Stay with existing pattern

2. **Are you using React 19+ or vanilla TS?**
   - Yes → Map Components
   - React < 19 → Core API

3. **Do you need fine-grained control over view lifecycle?**
   - Yes → Core API (`new MapView(...)`)
   - No → Map Components

## Setup Checklist

- [ ] `pnpm add @arcgis/map-components @arcgis/core @esri/calcite-components`
      (Calcite ^5.0 — alinear major con el SDK)
- [ ] Import component CSS: automatic via npm for Map Components
- [ ] Asset path: en 5.0 normalmente NO se requiere setAssetPath (default = CDN del SDK).
      Solo configurarlo si se hospedan assets localmente, usando la versión 5.0.x correspondiente.
- [ ] Configure API key: `esriConfig.apiKey = import.meta.env.VITE_ARCGIS_API_KEY`

## Anti-patterns (one-liner reminders)

- ❌ Don't use `@arcgis/map-components-react` for React 19+ (use components + event listeners)
- ❌ Don't access component methods on ref before `arcgisViewReadyChange`
- ❌ Don't import the `__esri` namespace (no longer supported as of 5.0 — use individual ESM type imports)
- ❌ Don't pin Calcite to 3.x (that's the 4.x era — use ^5.0)

- `SKILL.es.md` — guía completa en español
```

## 10. Plantillas de `scripts/`

### 10.1 `scripts/scaffold.sh`

Script bash idempotente que crea un proyecto funcional. Cumple:

1. Detecta si el directorio destino existe; pregunta antes de sobrescribir
2. Usa pnpm por defecto, npm como fallback
3. Pinea versiones del SDK explícitamente (rango ^5.0, resuelve a 5.0.x)
4. Termina con instrucción exacta para ejecutar

```bash
#!/usr/bin/env bash
set -euo pipefail

PROJECT_NAME="${1:-my-arcgis-app}"
PKG_MANAGER="${PKG_MANAGER:-pnpm}"

# Validación
if [ -d "$PROJECT_NAME" ]; then
  echo "❌ Directory '$PROJECT_NAME' already exists. Aborting."
  exit 1
fi

# Creación
echo "📦 Creating Vite + TS project: $PROJECT_NAME"
$PKG_MANAGER create vite@latest "$PROJECT_NAME" --template vanilla-ts -- --quiet
cd "$PROJECT_NAME"

# Dependencies — Calcite alineado al major del SDK (^5.0), NO 3.x.
echo "📦 Installing ArcGIS dependencies..."
$PKG_MANAGER add \
  "@arcgis/map-components@^5.0" \
  "@arcgis/core@^5.0" \
  "@esri/calcite-components@^5.0"

# Boilerplate
# Nota 5.0: setAssetPath de Calcite normalmente NO es necesario — el SDK provee
# el asset path por defecto desde su CDN. Solo configúralo si hospedas los assets
# localmente o en un CDN propio, usando la versión 5.0.x correspondiente.
cat > src/main.ts <<'EOF'
import "@arcgis/map-components/dist/components/arcgis-map";
import "@arcgis/map-components/dist/components/arcgis-zoom";
import "@esri/calcite-components/dist/components/calcite-shell";
import esriConfig from "@arcgis/core/config";

esriConfig.apiKey = import.meta.env.VITE_ARCGIS_API_KEY as string;

const map = document.querySelector("arcgis-map");
map?.addEventListener("arcgisViewReadyChange", (e) => {
  console.log("View ready:", (e as CustomEvent).detail.view);
});
EOF

cat > index.html <<'EOF'
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <title>ArcGIS Map App</title>
  <style>html,body,arcgis-map{margin:0;height:100%;width:100%}</style>
</head>
<body>
  <calcite-shell>
    <arcgis-map basemap="topo-vector" center="-118.24,34.05" zoom="12">
      <arcgis-zoom slot="top-left"></arcgis-zoom>
    </arcgis-map>
  </calcite-shell>
  <script type="module" src="/src/main.ts"></script>
</body>
</html>
EOF

cat > .env.example <<'EOF'
VITE_ARCGIS_API_KEY=your_arcgis_api_key_here
EOF

echo "✅ Done. Next steps:"
echo "   cd $PROJECT_NAME"
echo "   cp .env.example .env  # and add your API key"
echo "   $PKG_MANAGER dev"
```

## 11. Convenciones de código, naming y comentarios

### 11.1 Naming de skills

- **Patrón:** `arcgis-<dominio>-<sub-dominio?>`
- **Case:** kebab-case
- **Largo:** 2-4 palabras (ej. `arcgis-core-maps`, `arcgis-feature-effects`)
- **Excepciones:** las 4 nuevas de 5.0 mantienen el nombre del paquete (`arcgis-ai-components`, `arcgis-charts`, etc.)

### 11.2 Naming en código TypeScript

```typescript
// ✅ Imports
import Map from "@arcgis/core/Map.js";              // PascalCase para clases
import * as route from "@arcgis/core/rest/route.js"; // namespace para módulos

// ✅ Variables
const map = new Map({ basemap: "topo-vector" });    // camelCase
const MAX_ZOOM = 22;                                 // UPPER_SNAKE para constantes

// ✅ Tipos
type LayerConfig = { url: string; outFields: string[] };  // PascalCase
interface MapOptions { ... }
```

### 11.3 Imports — orden obligatorio

```typescript
// 1. Side-effect imports (CSS, components registration)
import "@arcgis/map-components/dist/components/arcgis-map";

// 2. Type imports
import type MapView from "@arcgis/core/views/MapView";

// 3. Default + named imports del SDK Core
import Map from "@arcgis/core/Map.js";
import FeatureLayer from "@arcgis/core/layers/FeatureLayer.js";

// 4. Imports relativos
import { myHelper } from "./utils";
```

### 11.4 Extensiones `.js` en imports TS

El SDK requiere `.js` al final para resolver subpath exports:

```typescript
// ✅
import Map from "@arcgis/core/Map.js";

// ❌
import Map from "@arcgis/core/Map";
```

| Idioma del archivo | Comentarios en código |

## 22. Smoke tests (build)

### Qué validan

Que el código compila y construye. No verifica que se renderiza correctamente.

### Implementación

Por cada skill que tenga `scripts/snippet-*.ts`:

1. CI crea un proyecto Vite temporal
2. Instala dependencias del frontmatter `packages:`
3. Copia el snippet a `src/main.ts`
4. Corre `tsc --noEmit`
5. Corre `vite build`
6. Falla si alguno falla

### Estructura del test

## 23. Integration tests (Playwright)

### Qué validan

Que el código no solo compila sino que **renderiza correctamente** en navegador. Verifica el comportamiento end-to-end.

### Implementación

Playwright corre proyectos generados por `scaffold.sh` en navegador headless:

```typescript
// tests/integration/arcgis-core-maps.e2e.ts
import { test, expect } from "@playwright/test";

test("starter-app renders map with topo-vector basemap", async ({ page }) => {
  await page.goto("http://localhost:5173"); // proyecto previamente buildeado
  const map = page.locator("arcgis-map");
  await expect(map).toBeVisible();

  // Esperar evento ready
  await page.waitForFunction(() => {
    const el = document.querySelector("arcgis-map") as any;
    return el?.view?.ready === true;
  }, { timeout: 30000 });

  // Validar basemap
  const basemap = await page.evaluate(() => {
    const el = document.querySelector("arcgis-map") as any;
    return el?.basemap;
  });
  expect(basemap).toBe("topo-vector");
});
```

### Frecuencia

- Manual antes de release
- Semanal vía GitHub Actions cron
- Pre-release (RC) obligatorio

### Cobertura objetivo

Cubrir las **10 skills más críticas** (Core 4 + Layers 2 + Visualization 1 + Interaction 1 + Services 2). Las demás van a smoke + validation solamente.

## 24. Triggering evals

### Qué validan

Que la **descripción del frontmatter** dispara la skill cuando debe, y no dispara cuando no debe.

### Implementación

Inspirado en el patrón del skill-creator de Anthropic. Por cada skill, un archivo `tests/evals/<skill-name>.eval.json`:

```json
{
  "skill_name": "arcgis-core-maps",
  "should_trigger": [
    "I need to create a 2D map with the latest ArcGIS SDK",
    "How do I initialize a SceneView in TypeScript?",
    "What's the difference between Map Components and Core API?",
    "Show me how to use arcgis-map component",
    "Necesito crear un mapa con ArcGIS y Vite"
  ],
  "should_not_trigger": [
    "How do I query a FeatureLayer?",
    "I want to add a popup to my map",
    "Show me how to OAuth2 with ArcGIS"
  ]
}
```

El script `scripts/eval-descriptions.mjs` invoca `claude -p` con cada prompt y verifica si la skill aparece en `available_skills` consultados.

### Métrica

- **Trigger rate** (true positives) ≥ 80%
- **False positive rate** ≤ 10%

### Frecuencia

- Semanal vía cron
- Antes de cambios en la `description` del frontmatter

## 30. Flujo de versionado y release

### Estrategia de versionado

**SemVer 2.0.0** aplicado al repo completo:

- **MAJOR (1.x → 2.x):** breaking change que requiere cambios en consumers (ej. removed skills, structural rework)
- **MINOR (1.0 → 1.1):** nuevas skills, nuevas references, nuevas features de CLI
- **PATCH (1.0.0 → 1.0.1):** fix de typos, bugs en scripts, links rotos

### Flujo de release

```
1. PR sobre main → merge
2. CHANGELOG.md update (manual o changesets)
3. Bump version (pnpm version <major|minor|patch>)
4. Git tag (git tag v1.0.0 && git push --tags)
5. CI Release workflow → genera GitHub Release con notes
6. Publish (si aplica) → marketplace + agentskills.io
7. Anuncio público → CHANGELOG.md visible en docs
```

### Versionado por skill individual

Cada skill tiene su propia versión en frontmatter (`version: x.y.z`). Una skill puede ir a `1.0.0` antes que el repo si está madura.

## Apéndice C — Glosario de errores comunes

### Error 1: "Cannot find module '@arcgis/map-components/dist/components/arcgis-map'"

**Causa más común:** `moduleResolution` mal configurado.

**Fix:** En `tsconfig.json`:

```json
{ "compilerOptions": { "moduleResolution": "bundler" } }
```

### Error 2: "Map shows grey/blank canvas"

**Causa más común:** API key no configurado.

**Fix:** Verificar `.env` y `esriConfig.apiKey = import.meta.env.VITE_ARCGIS_API_KEY`.

### Error 3: "Calcite icons render as empty boxes"

**Causa más común:** Versión de Calcite desalineada con el SDK, o asset path mal configurado al hospedar assets localmente.

**Fix:**

1. Usar `@esri/calcite-components` **^5.0** (alineado al major del SDK 5.0), no 3.x.
2. En 5.0 normalmente NO se necesita `setAssetPath` (default = CDN del SDK). Si hospedas assets localmente:

```typescript
import { setAssetPath } from "@esri/calcite-components/dist/components";
// usar la versión 5.0.x correspondiente, no 3.3.3
setAssetPath("https://js.arcgis.com/calcite-components/5.0.0/assets");
```

### Error 4: "Cannot read property 'view' of undefined"

**Causa más común:** Accediendo a `arcgis-map.view` antes de `arcgisViewReadyChange`.

**Fix:**

```typescript
const map = document.querySelector("arcgis-map");
map?.addEventListener("arcgisViewReadyChange", (e) => {
  const { view } = (e as CustomEvent).detail;
  // Usar view AQUÍ
});
```

### Error 5: "AMD require is not defined"

**Causa:** Código legacy usando `require()` con CDN 5.0.

**Fix:** Migrar a `$arcgis.import()`:

```javascript
const Map = await $arcgis.import("@arcgis/core/Map.js");
```

### Error 6: "Cannot find package '@arcgis/embeddable-components'"

**Causa:** Embeddable Maps NO tiene paquete npm.

**Fix:** Usar vía CDN con script tag + custom element (embeber un WebMap guardado por `item-id`), no `pnpm add`.
